Fallout.Fallout — Module
Fallout

Test impact analysis (regression test selection): run only the tests a change can affect. Works for any Julia package whose testsets can be run by name through a runner script that takes a regex (ReTest's convention), or whose test files are suites of their own that a runner script runs by path (--suites).

build run every top-level testset in its own process with --code-coverage and save which source lines each one executed, with the git commit of the tree merge join the maps of a sharded build select compare the working tree (or --to REV) with a base and print the testsets whose executed code, or whose referenced definitions, changed run select, then run the selected testsets through the runner

The selector never loads the package under test. Units (unit, unit_cache) run inside a test process and cache results while the code they ran is unchanged. See README.md.

Fallout.CoverageMap — Type

A coverage map. definitions lists each source file's function headers at commit, in file order, and a testset's coverage names functions by their position in that list. project is the Julia project the runner runs in, relative to the root. suites is the directory whose files matching suite_pattern are the testsets (empty when the testsets are the @testsets of tests). A function is known by its file and its signature header without whitespace, so methods sharing a name are told apart by their arguments, and an edit elsewhere in the file leaves the identity alone.

Fallout.Worker — Type

One testset's coverage run: a fresh Julia process running runner in project on the testset's name (its path when by_path, else a ReTest regex) with an LCOV tracefile of its own, counting lines only under covered (an @path selector, so dependencies keep their package images). Fallout.build_map — Method
build_map(root, out; tests, suites, suite_pattern, sources, runner, project, jobs, timeout, only, shard, shards, commit, environment)

Run every top-level testset of tests (found statically, following literal includes), or with suites every file under that directory whose name matches suite_pattern, in its own process, running runner in the Julia project project (relative to root), and write the map to out. Testsets are ordered by source length and dealt round-robin into shards shards; this call runs shard shard (merge joins the shards' maps). The shard's smallest testset runs alone first, so the coverage-flagged precompilation finishes before the rest start together. The map lists the functions of every .jl file under sources (as parsed in root) and records, per testset, which ran.

Fallout.select_testsets — Method
select_testsets(root, map, base, target)

Select the map's testsets affected by the change from revision base to target (the working tree when target is empty). Rules, in the order they appear in the reasons:

  • full suite: a Project.toml or Manifest.toml changed, or with suites the runner
  • runs changed code: the testset executed a line of a function whose body changed
  • dispatch: a function's signatures were added, removed or edited, so any testset that ran any method of that name may now dispatch differently
  • mentions changed definition: a struct, type, const, global, macro or other non-function item changed, and the testset executed a function that mentions its name (or a name defined by something that mentions it), or its own code mentions it
  • edited testset, new testset, changed test helper, changed fixture file
  • static analysis: the testset reads or analyses code and any .jl file changed

Fallout.unit_cache — Method
unit_cache(; track = :coverage, root, dir = ROOT/.fallout/units, project = Base.active_project(), refresh = false)

A unit cache for the code under root, parsed now. With track = :coverage (Julia started with --code-coverage=@ROOT) a unit depends on the items it ran; with track = :sources it depends on every .jl file under root (default: the working directory). Every unit also depends on Julia's version and project's Project.toml, manifest and preferences.
